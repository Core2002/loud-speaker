# loud-speaker

基于 Rust + [cpal] 的实时音频桥接工具：把**麦克风**采集到的声音经过内部缓冲后，送到**扬声器**播放；既可以在同一台电脑上直接扩音，也可以跨机器通过 WebSocket 传输（A 机采麦、B 机放声）。

> 已适配不同的硬件：麦克风与扬声器的采样率、声道数不一致时（例如单声道麦克风 + 立体声扬声器，或 44.1kHz 与 48kHz 混搭），程序会自动做单声道归一、采样率重采样与声道扩展，避免拖音、变调、无声或延迟无限增大等问题。

[cpal]: https://github.com/RustAudio/cpal

## 工作原理

```
模式 0（单机）
  麦克风 ──降混 mono──▶ AudioBus ──重采样/升混──▶ 扬声器

模式 1（服务端）                         模式 2（客户端）
  麦克风 ──降混 mono──▶ AudioBus           WebSocket ──解码──▶ AudioBus ──重采样/升混──▶ 扬声器
                          │                     ▲
                          └── 每 20ms 打包 ──▶ WebSocket 广播 ──┘
```

- `mic`：输入设备按**自身默认格式**采集，逐帧降混成单声道写入有界环形缓冲。
- `loud`：输出设备按**自身默认格式**播放，每输出一帧从缓冲拉取一个单声道样本（采样率不同时线性重采样），再复制到所有输出声道。
- 缓冲保留约 **50ms 播放余量**，并设了上限（约 250ms），既避免贴边抽空产生断续，也避免生产者过快导致延迟和内存无限增长。
- 服务端每 **20ms** 从麦克风缓冲取一次数据并发给所有客户端；客户端把收到的数据写入本地缓冲，再由 `loud` 播放。

## 运行模式

程序通过 `-d/--debug <MODE>` 选择运行模式：

| 模式 | 含义 | 需要的设备 | 现状 |
| --- | --- | --- | --- |
| `0` | 单机扩音：同一台电脑上 mic → 扬声器 | 麦克风 + 扬声器 | ✅ 可用 |
| `1` | 服务端：采集麦克风 + WebSocket 广播给所有客户端 | 麦克风 | ✅ 可用 |
| `2` | 客户端：连接服务端 + 本地扬声器放声 | 扬声器 | ✅ 可用 |

- 服务端只采集、不放声，可无头运行；客户端只放声，不采集。
- 一个服务端可同时向多个客户端广播；客户端断线后每 1 秒自动重连，连接后 5 秒收不到数据也会主动重连。
- 客户端会读取服务端在会话开始时发送的音频格式（采样率），并据此重新配置重采样，因此两端硬件采样率不同也能正常播放。

## 构建与运行

```bash
cargo build --release
```

### 模式 0：单机扩音

```bash
cargo run --release -- -d 0
# 或
./target/release/loud-speaker -d 0
```

对着麦克风说话，声音会从本机扬声器实时放出。

### 模式 1 / 2：局域网传声

在 **A 机**（接麦克风）启动服务端。默认监听 `0.0.0.0:8080`：

```bash
cargo run --release -- -d 1
# 指定端口
cargo run --release -- -d 1 --bind 0.0.0.0:9000
```

在 **B 机**（接扬声器）启动客户端，指向 A 机的 IP：

```bash
cargo run --release -- -d 2 --server ws://192.168.1.10:8080
# 同一台机器上测试
cargo run --release -- -d 2 --server ws://127.0.0.1:8080
```

### 命令行参数

| 参数 | 说明 | 默认值 |
| --- | --- | --- |
| `-d, --debug <MODE>` | 运行模式：`0` / `1` / `2` | `0` |
| `-b, --bind <ADDR>` | 服务端监听地址（模式 1） | `0.0.0.0:8080` |
| `-s, --server <URL>` | 服务端地址（模式 2） | `ws://127.0.0.1:8080` |

## 传输协议

- 连接建立后，服务端先发送一条文本消息：`LSPK1 <采样率> <声道数>`（当前固定为单声道）。
- 之后每个二进制消息是一批**单声道 `f32` 小端** PCM 样本，采样率与 hello 一致；服务端每 20ms 发送一批。
- 48kHz 时带宽约 **192 KB/s（≈1.5 Mbps）**，局域网/Wi-Fi 均可承载。
- 协议没有加密与鉴权，也不做丢包重传（实时音频宁可跳过也不累积延迟），请只在可信局域网或 VPN 内使用。

## 环境要求

- Rust（edition 2021）
- 对应模式所需的默认音频设备（模式 0：麦克风 + 扬声器；模式 1：麦克风；模式 2：扬声器），找不到会直接报错退出
- 主要在 Windows（cpal WASAPI）上验证；其他平台取决于 cpal 后端支持情况
- 跨机器使用时，需要在 A 机防火墙放行所用端口（默认 8080）

## 延迟与调参

- 单机模式延迟主要来自 `AudioBus` 的 50ms 播放余量，约数十毫秒。
- 网络模式还会叠加 20ms 打包周期与网络抖动，局域网下通常约 100ms。
- 想进一步降低延迟或提高抗抖动能力，可调整 `src/lib.rs` 中 `AudioBus::from_rates` 的 `0.05`（播放余量）与 `0.25`（延迟上限）。
- 两端声卡时钟存在微小漂移，缓冲达到上限时会丢弃最旧的数据以维持实时性；偶发的轻微跳帧属正常现象。

## 注意事项

- 扩音即“麦 → 箱”实时回放，麦克风对着扬声器会形成**啸叫/回授**，请调整方向与音量；网络模式下尤其注意 B 机扬声器的声音不要被 A 机麦克风拾取。
- 播放起点约有一小段（~50ms 余量对应的）静音缓冲，属正常现象。
- 服务端默认监听 `0.0.0.0`，请勿直接暴露到公网。
